## Decisions recorded (see plan; amendments in doc 07 §4.5/§4.8/§8, doc 08 §4/§10, doc 09 §2.9)
1. Seed users are created by the provisioning service, not listed in the realm export.
2. `tenant_id` claim is multivalued (aggregate); exactly one value is required.
3. Idempotency keys arrive in M1 and live in `platform.idempotency_keys` keyed by `(user_id, route, key)`.
4. `audit.audit_log` is a plain indexed table; monthly partitioning deferred.
5. Bootstrap admins get the default department `ADMIN` (`Διοίκηση`/`Administration`).
6. Minimal SPA login in M1; full UI in M3.
7. Dev-only: direct access grants on `frontend-spa`; PostgreSQL published on `127.0.0.1:5432`.
8. Audit taxonomy extended with `admin.employee.updated|deactivated` and `admin.department.*`.

## Problems encountered and how they were solved
| Problem | Resolution |
|---------|------------|
| FastAPI 0.162 returns a plain `Response` (media type `application/json`) from its fast serialisation path, not a `JSONResponse`; the idempotent route did not store replies | Detect JSON by media type, read `response.body` |
| SQLAlchemy 2.1 types `select(Model)` as `Select[Model]` (2.0: `Select[tuple[Model]]`) | Repository helpers annotated accordingly |
| Protocol attributes are invariant: `SqlAlchemyUnitOfWork` did not satisfy `UnitOfWork` until the repository attributes were declared with the port types | Class-level annotations on both unit-of-work implementations |
| Dataclass with `slots=True` cannot read field defaults through `cls.field` | `cls()` instance for defaults in `TenantSettings.from_dict` |
| `respx.mock(...)` with arguments creates a separate router; routes registered on the global router were not matched | `respx_mock` fixture + `@pytest.mark.respx` |
| Parallel tool calls: a `cd` did not apply and files were written to the repository root | Absolute paths for all generated files |

## Changes versus the plan
- `backend-admin` needs the `realm-management` role **`view-realm`** in addition to `manage-users/view-users/query-users/query-groups` (reading realm role representations for role mappings); added to the realm export.
- `ensure_tenant` re-verifies the Keycloak group on every run (a re-imported realm has no groups) instead of trusting the stored `keycloak_group_id`.
- The RLS migration helper lives in the package (`infrastructure/db/rls.py`), not next to the Alembic scripts (migrations are also loaded by the readiness check at API start-up).
- nginx now passes a client-supplied `X-Request-Id` through (`map` on `$http_x_request_id`) instead of always generating one; found by the live suite.
- Unique-constraint violations at flush time are translated to `409 conflict` (not only at commit).
- `/me` in the SPA binds the token explicitly (a sign-out race logged one 401 in the browser console).
