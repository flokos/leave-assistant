## Decisions and deviations (also in the docs)
1. **Default from the pre-registered rule**:
   - pgvector stays (Chroma gives identical rankings and is slower);
   - hybrid stays (vector-only +0.009, CI touches 0);
   - **reranker B on ONNX fp32**: A is +0.034 nDCG@5 but about 13× slower per turn;
   - **τ 0.5 → 0.22**.
2. **Reranker A's runtime variants were not timed** (user decision): its PyTorch latency (M6 about 73 s per turn; a
   52-minute run aborted here) already rules it out on this CPU.
3. **Live answers pinned to Mistral** (`answers --providers mistral`). With the production order, Gemini's answer
   model ran out of its free quota (20 requests per day), and the router answered 15 of 18 items with Mistral and 3
   with Gemini, a random mix that would confound the comparison.
4. **RAGAS judge `mistral-large-4`**:
   - planned: `ministral-14b-2512`, which would have judged its own answers;
   - next choice: `mistral-medium-2604`, but Medium and Small have 0 requests/min on the free plan;
   - paced at 0.12 requests/s for the 20k tokens/min limit, about 1 h per repetition.
5. **Live agent scenarios on Mistral only**: Gemini's quota was gone, and 11 scenarios need more than a day's 20
   requests.
6. **Tool selection reported two ways**: pre-registered "expected tool called" (10/11) and the harness's stricter
   "returned ok" (8/11).
7. **The verifier fallback is not changed in M9.** It is measured (`verifier_exhausted`) and goes to M10 (R-36),
   because a new outcome touches the API, persistence and UI.
8. **Embedded api limit 3G → 3.5G.** With ONNX, a chat turn and then the document suite peaked at 3.06 GB of the
   3 GB limit (PyTorch 2.86 GB), and the api was OOM-killed once. ONNX is the only runtime that meets
   NFR-PERF-01. A cgroup limit caps usage rather than reserving it. Disabling ONNX Runtime's memory arena saved
   nothing.
9. **Langfuse v4 trace reads** go through `GET /api/public/v2/observations` (the trace list endpoint is gone).

## Problems found and how they were solved
| Problem | Resolution |
|---------|------------|
| Hybrid and vector-only ranked identically on all 49 queries: `websearch_to_tsquery` ANDs every word, so a whole question matched no chunk | the language leg ORs the stemmed terms; `simple` keeps websearch; integration test with a whole question; grid re-run (the first run is kept as `*-before-fts-fix`) |
| Every live answer failed with `internal-error`: `GEMINI_MODEL=` (empty) in `deploy/.env` overrode the default when sourced on the host (compose's `${X:-default}` treats empty as unset) | `env_ignore_empty=True` in Settings; unit test |
| The harness missed evidence: `search_policies` keeps its own `RetrievalService` reference, and contexts were rebuilt with the wrong policy | `ContextRecorder` observes `build_context` at both call sites; the gateway's retrieval is wrapped too; samples carry exactly what the LLM saw |
| `make chat-perf` measured 14 s with ONNX: it ran inside the running api, which had already loaded every model, so two copies shared 3 GB (cgroup at its limit 265,835 times, 3.2 GB swapped) | the target starts a one-off container; earlier PyTorch figures were close (3.79 vs 3.84 s) |
| The api was OOM-killed in the integration suite (embedded worker, ONNX) | measured both runtimes (3.06 vs 2.86 GB); limit 3.5G (decision 8); suite re-run green |
| RAGAS turned 429s into NaN: Medium and Small have no free quota | judge `mistral-large-4` with client-side pacing |
| Answer relevancy failed with `dict += dict`: langchain-mistralai 1.1.6 sums nested usage (not fixed upstream) | `JudgeChat` merges usage recursively; test |
| The session ended and both background jobs died: systemd-oomd killed the editor (and SeaweedFS) when the api, the integration suite, Langfuse, RAGAS and the desktop apps exceeded RAM and swap | long jobs run detached; RAGAS checkpoints each repetition; Langfuse stopped before integration tests; R-01 and the installation guide updated |
| Langfuse sync: the task returned no item id (scores would never attach), and `dataset.run_experiment` ran all 71 items | the id is returned; `client.run_experiment(data=sampled items)` |
| The int8 export failed: sentence-transformers names the avx2 file `model_quint8_avx2.onnx` | file name fixed |
| A runtimes run lost its in-memory results when stopped | `--variant` and a partial JSONL; `runtimes-report` rebuilds the table |
| Langfuse web: heap OOM; published port hung (Next.js bound to one network); ClickHouse refused to start (pool thresholds above the reduced pool) | 1 GB Node heap, `HOSTNAME=0.0.0.0`, healthcheck on 127.0.0.1; thresholds lowered with the pool |
| A self-matching `pkill -f` killed its own shell twice | stop processes by PID |
| `make test-e2e` failed once: the api ran real providers, but the chat specs expect the fake model | re-run with `LLM_PROVIDER_ORDER=fake`; the make help says so |
