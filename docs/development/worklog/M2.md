## Decisions recorded (plan decisions 1–12, all implemented)
Modification = new row (original `MODIFICATION_PENDING` → `CANCELLED`/`APPROVED`); exclusion constraint excludes
`MODIFICATION_PENDING`; documents advisory until M4; rollover in the worker loop; per-tenant request counters and
employee row locks; `security_invoker` balance view; calendar-year periods with per-period deductions; designation
is authoritative, HR fallback flagged, segregation enforced; need-to-know masking in one place (`views.py`);
`version` in bodies; notification records + outbox; audit actions `leave.request.*`, `ledger.entry.posted`,
`admin.config.changed`, `system.rollover`. Additional: the seed sick policy allows a negative balance so that
cap-exceeding sick leave reaches HR review (Q-02) rather than a balance rejection; four matrix additions
(`READ_LEAVE_CATALOGUE`, `ADJUST_LEDGER`, `READ_TENANT_BALANCES`, `MANAGE_OWN_NOTIFICATIONS`).

## Problems encountered and how they were solved
| Problem | Resolution |
|---------|------------|
| Protocol methods named `list` shadow `builtins.list` in later annotations of the same class (mypy: "Function … is not valid as a type") | `builtins.list[...]` in the ports and SQL repositories |
| Dataclass `slots=True` + reading defaults through `cls.<field>` | instance defaults |
| Events were written before the request row existed (FK violation in PostgreSQL only — the in-memory fakes have no FKs) | request row inserted first; an in-place save (`bump=False`) keeps `version = 1` after routing |
| A cap-exceeding sick request failed validation instead of reaching HR | sick policy `allow_negative = true` (ADR-0028 thresholds are tenant data); `within_cap` drives routing |
| FastAPI's `include_router` returns `_IncludedRouter` entries in `app.routes` (route inspection by path fails) | verified routes through tests, not by walking `app.routes` |
| 26 Dec 2026 is both Saturday and a holiday | holidays take precedence in `excluded_dates` (informative) |

## Changes versus the plan
- The seed sick-leave policy allows a negative balance (`allow_negative = true`) so that a request beyond the
  remaining cap is routed to HR review per Q-02 instead of being rejected by the balance check (doc 01 §6.1 note).
- Four permission-matrix rows added for catalogue reads, ledger adjustments, tenant balances and own notifications
  (doc 08 §5.2).
- Request creation writes the row before its events (foreign key) and saves the routed status in place, so a fresh
  request has `version = 1`; every later write bumps the version.
- Company administrators may *read* a request (matrix: tenant read of department requests) but see absence only
  (`leave_type` and `reason` null); doc 09 listed "owner, approvers, H" — the matrix wins, masking applies.
- Pending days in `leave_balances` are counted in the request's start year (a request spanning two years is
  deducted per period on approval; its pending days are an approximation documented in doc 07).
