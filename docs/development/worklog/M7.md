## Decisions and deviations (also in the docs)
1. **Native function calling, text-rendered loop history** (plan decision 1).
2. **Tools are bound by role and by intent group.** The plan bound every role-permitted tool. JSON schemas cost
   about 45 e5 tokens per parameter: 1,600 tokens for the employee set, 2,028 for all 13. Approval and availability
   questions now bind the approver group; every other business question binds the self-service group. The
   tool-schema budget is the measured largest group (1,300), and the plan prompt fits history and results into what
   the 3,500 total leaves.
3. **`validate_leave_request` is not bound.** It stays in the catalogue and the gateway, but `prepare_leave_request`
   validates by itself. Live, Gemini read "Can I request five days off?" as an eligibility question, validated, and
   answered instead of showing a card.
4. **User input has its own benign reference set** (`benign_user_v1`); documents keep `benign_v1`. The heuristics
   gained a "forget what you were told" pattern in both languages.
5. **Request numbers are not personal data**: they are excluded from Presidio detection.
6. **More deterministic answer checks for small models**: the balance answer must state the tool's available days;
   an answer may not claim a card or an action that did not happen; a request may not be answered with
   "shall I prepare it?".
7. **Business scenarios run on the integration database** (seeded fresh per test), not the dev database, so the
   dev data never accumulates requests and approvals.
8. **S13 uses the Christmas holidays** instead of New Year: booking next year fails before the yearly grant (R-32).
9. Proposal expiry is the tenant setting (15 minutes), not doc 04's 30. A new message supersedes an open card.

## Problems found and how they were solved
| Problem | Resolution |
|---------|------------|
| **M6 bug: every policy turn duplicated the history** (9 messages after two turns): the Knowledge subgraph returned its copy of `messages` and the `operator.add` reducer appended it | output schemas on every subgraph and an id-based reducer; regression test on history length |
| **M6 bug: the 90-day conversation cleanup was never scheduled** (the setting existed, the task did not) | scheduled in the worker with `proposal.expire`; test on the task list |
| The fake's `<user>` regex matched from "<user> tags" in the system prompt to the real message, swallowing the plan prompt's example "December 14" | captures may not contain `<user>` |
| Greek day counts ("3 μέρες") failed against folded text (final ς → σ) | patterns written in folded form |
| JSON tool schemas were 1,600 e5 tokens against a 700 budget | property descriptions dropped (formats stated once in the plan prompt), shorter descriptions, intent groups, adaptive fitting (decision 2) |
| Parallel e2e specs used one account: "New conversation" fell back to the latest conversation, so a message landed in the other test's thread and superseded its card | the chat page keeps "New" new (a real bug since M6); the actions spec uses Brightwater users; regression test |
| Live: Presidio read request numbers as phone numbers ("LR-[phone withheld]") | request numbers excluded from detection; PII test |
| Live: "Approve request LR-…" scored 0.79 (medium → read-only) and was blocked once pseudonymised | `benign_user_v1` for user input; a combined v2 broke an imperative-injection paraphrase in documents (0.713 → 0), hence separate sets plus a heuristic |
| Live: the fast classifier answered the two-part headline with `clarify` | a deterministic request pattern in the pre-router, and a mixed-intent rule in `classify` v2 |
| Live: Gemini answered "Can I request…?" with a validation and "would you like me to prepare it?" | prompts say prepare straight away; `validate_leave_request` no longer bound (decision 3) |
| Live: `ministral-14b` passed an unknown leave type (empty result, "no days left"), claimed "I have prepared … on the card" without a card, and asked "shall I prepare it?" | unknown leave types return all balances with a note; balance, phantom-action and permission-question checks with deterministic fallback (decision 6) |
| Failed e2e runs left documents and a request behind; the next runs hit pagination and an overlap | specs page through tables with `findRow`; the leftovers were removed through the API |
| The drift tests reported the new partial and expression indexes | listed with the other raw-SQL indexes |
| Edits applied by scripts silently missed lines that ruff had re-wrapped | the patch scripts assert every match before writing (as in M6) |
