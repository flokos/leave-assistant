## Decisions recorded (plan decisions 1–8, all implemented)
Typed client with idempotency middleware; navigation cosmetic (every page handles 401/403); workspaces limited to
what the backend offers today (no stubs for M4–M8 pages); OIDC session in `sessionStorage`; Playwright against the
Compose stack, outside CI (Q-13); dayjs for display only — leave dates never pass through a timezone; route-level
code splitting; notification texts rendered client-side from `type` + `params`.

## No business logic in the frontend (review checklist, FR-UI-04)
- Working days, excluded dates, balances, routing, document requirements and every violation come from the
  `ValidationReport` / simulation endpoint; the client renders them and only *disables* the submit button when
  `valid` is false.
- Status changes happen only through the API (`submit`, `modify`, `cancel`, `approve`, `reject`); the detail drawer
  decides merely which buttons to *show* (modifiable/cancellable sets of doc 07) — the API answers `leave/invalid-state`
  if the client is stale, and the problem is displayed.
- Roles gate routes for UX only; the `/me` roles come from the backend; the API re-authorises every call (the
  E2E "employee opens `/admin/employees`" case shows the polite notice, and the API would answer 403).
- Masking (reason / leave type for company administrators) is applied by the backend; the client shows "Absence"
  when `leave_type` is null.

## Problems encountered and how they were solved
| Problem | Resolution |
|---------|------------|
| TanStack Query 5.106 `onError` takes four arguments (`error, variables, onMutateResult, context`) | `useApiMutation` forwards all four |
| `react-refresh/only-export-components`: helper exports in component files | `app/menu.tsx` (`menuItemsFor`), `notifications/text.ts`, `shared/errors.ts` |
| `openapi-fetch` captures `globalThis.fetch` when the client is created (test stubs ignored) and `new Request()` needs an absolute URL under Node | client created with a lazy `fetch` and `window.location.origin` as base URL (same origin in the browser) |
| Testing Library auto-cleanup is inactive with vitest `globals: false` → duplicate elements between tests | explicit `afterEach(cleanup)` in `test-setup.ts` |
| vitest collected the Playwright specs; i18n flattening broke on dotted leaf keys (`request.submitted`) | `include: src/**`; flatten to a path → value map |
| Ant Design tables/modals under jsdom take 4–6 s on this host (5 s default timeout) | `testTimeout: 20_000` |
| Async event handlers (`form.validateFields`, `mutateAsync`) produced unhandled rejections on expected failures | `shared/async.handle()` — errors are already surfaced by the form / toast / `ProblemAlert` |
| Ant Design `DatePicker`/`RangePicker` drop `data-testid`; password inputs have no `textbox` role | wrapper `div` anchors; Keycloak form targeted by `#username` / `#password` / `#kc-login` |

## Changes versus the plan
- `MePanel` stays on `/system` (status page shows the principal) instead of being dropped; the M1 `AuthControls`
  component was removed (the shell header replaced it).
- The bell shows the number of unread notifications returned by `GET /notifications?unread=true&limit=100` (no count
  endpoint exists); fine for records-only notifications, to revisit in M8.
- Employee names on the HR balances page are resolved through `/team/employees` (tenant scope for HR / company
  administrators) rather than an extra endpoint.
- vitest `testTimeout` raised to 20 s; the Playwright suite runs through `make test-e2e` with `deploy/.env` exported
  so the seed password is shared.
- The shared Ant Design chunk exceeds Vite's 500 kB warning (ADR-0024 lists the bundle size as the accepted
  disadvantage); vendor chunking is a follow-up, not an M3 criterion.
