The old target ran the measuring process *inside* the running api container, next to the api server that had already
loaded every model at start-up. Two copies of the models shared the container's 3 GB limit: the cgroup reached it
265,835 times and had 3.2 GB swapped out. The ONNX run tipped over the limit and the PyTorch run only just
fitted, so these rows measure swapping. M6/M7 used the same target (p50 3.12–3.97 s), so their figures were
probably inflated too. `make chat-perf` now starts a one-off container (same image, environment and memory
limit, no second copy).

Warm-up turn (first turn after start, model loading): 54–58 s in every container run.
