# 09 — API Contracts

The OpenAPI document generated by FastAPI (`GET /api/v1/openapi.json`) is the executable contract; a snapshot is
committed to `docs/api/openapi.json` at every milestone and diffed in CI. This document fixes the conventions
and the endpoint catalogue so that the frontend, n8n workflows and tests can be built against stable shapes.

## 1. Conventions

| Topic | Rule |
|-------|------|
| Base path | `/api/v1` (browser traffic is proxied by the frontend container on the same origin) |
| Auth | `Authorization: Bearer <Keycloak access token>`; service accounts use client-credentials tokens |
| Content | JSON (`application/json`); uploads `multipart/form-data`; streaming `text/event-stream` |
| Errors | RFC 9457 `application/problem+json`: `type` (URI under `urn:leave-assistant:problem:`), `title`, `status`, `detail`, `instance`, `request_id`, optional `errors[]` for field validation |
| IDs | UUID strings; request numbers are human-readable (`LR-2026-000123`) but never used as keys |
| Dates/times | leave dates `YYYY-MM-DD` (civil dates); timestamps RFC 3339 UTC |
| Pagination | cursor-based: `?limit=50&cursor=…` → `{ "items": [...], "next_cursor": "…" \| null }` |
| Filtering/sorting | explicit query parameters per endpoint; no generic query language |
| Idempotency | `Idempotency-Key: <uuid>` **required** on every state-changing request (POST/PATCH/DELETE) except OAuth callbacks; replay returns the stored response (same status); different body under the same key → `409 idempotency-mismatch`; keys expire after 24 h |
| Concurrency | mutable aggregates carry `version`; updates send the version they read; stale → `409 version-conflict` |
| Localisation | `Accept-Language: el` or `en` selects rendered strings (validation messages, notification previews); data is language-neutral |
| Correlation | `X-Request-Id` accepted or generated; echoed in responses and problems; present in logs/traces |
| Rate limiting | `429` with `Retry-After`; headers `X-RateLimit-Limit/Remaining` |
| Versioning | additive changes only within v1; breaking changes → `/api/v2` with a deprecation window |
| Authorization | every endpoint lists roles; scope checks (self/department/tenant) happen in services; denials → `403 authorization-denied` (never `404` leaks for cross-tenant IDs: cross-tenant resources are invisible, so they yield `404 not-found`) |

### Problem types
`validation-error`, `authorization-denied`, `not-found`, `version-conflict`, `idempotency-mismatch`,
`rate-limited`, `leave/invalid-dates`, `leave/overlap`, `leave/insufficient-balance`, `leave/notice-period`,
`leave/max-consecutive`, `leave/retroactive-not-allowed`, `leave/document-required`, `approval/not-permitted`,
`approval/segregation-of-duties`, `approval/step-not-pending`, `document/unsupported-type`, `document/too-large`,
`document/not-retrievable`, `document/acl-not-allowed`, `chat/thread-not-owned`, `chat/blocked-input`,
`chat/proposal-expired`, `chat/proposal-hash-mismatch`, `provider/unavailable`, `calendar/connection-expired`,
`calendar/not-connected`, `supporting/not-permitted`, `tenant/suspended`.

## 2. Endpoint catalogue

Roles: E = employee, M = manager, H = HR admin, C = company admin, P = platform admin, A = automation (n8n),
`*` = any tenant role (E/M/H/C). "Idem" = requires `Idempotency-Key`.

| Method | Path | Roles | Purpose |
|--------|------|-------|---------|
| GET | `/healthz` | public | Liveness |
| GET | `/readyz` | public | DB, storage, Keycloak JWKS reachable; models loaded |
| GET | `/me` | any authenticated | Principal: user, tenant, roles, employee summary, locale, feature flags, pending interrupt count |
| PATCH | `/me/preferences` | any (Idem) | `locale`, notification channel preferences |

### 2.3 Leave (self-service)
| Method | Path | Roles | Purpose |
|--------|------|-------|---------|
| GET | `/leave/types` | * | Leave types and rules summary for the tenant |
| GET | `/leave/balances?year=` | * | Own balances per type: `balance_days`, `pending_days`, `available_days`, ledger summary |
| GET | `/leave/ledger?type=&year=` | * | Own ledger entries |
| GET | `/leave/working-days?start=&end=` | * | Working-day count and excluded dates |
| POST | `/leave/requests/validate` | * | Dry-run validation → `ValidationReport` (no side effects, no key needed) |
| POST | `/leave/requests` | * (Idem) | Submit `{leave_type, start_date, end_date, reason?}` → `LeaveRequest` (status after routing) |
| GET | `/leave/requests?status=&from=&to=` | * | Own requests |
| GET | `/leave/requests/{id}` | owner, approvers, H | Request with steps, events, documents metadata |
| POST | `/leave/requests/{id}/modify` | owner (Idem) | New dates → re-validation, re-approval |
| POST | `/leave/requests/{id}/cancel` | owner (Idem); H for ACTIVE | Cancel/withdraw |
| POST | `/leave/requests/{id}/supporting-documents` | owner (Idem, multipart) | Upload sick-leave note (M4) |
| GET | `/leave/requests/{id}/supporting-documents` | owner, H | Metadata only (M4) |

M2 notes: `modify`/`cancel` bodies carry the request `version`, approval decisions the step `version`
(`409 version-conflict` when stale); `validate` and `/admin/approval-rules/simulate` are side-effect-free POSTs
without `Idempotency-Key`; `leave_type` is `null` in responses for viewers who may only see the absence
(company administrators); `/admin/holidays/import` takes `{"csv": "date,name_el,name_en[,recurring]…"}`;
`GET /notifications`, `POST /notifications/{id}/read` and `/notifications/read-all` exist from M2 (rendering and
e-mail delivery arrive in M8). Day quantities are JSON numbers (multiples of 0.5).

### 2.9 Platform administration (`/platform/*`, role P)

(creates the first company administrator — returns the employee, the default `ADMIN` department, the username and the

### 2.10 Internal (`/internal/*`, role A or the worker's internal token; not routed from the browser)

## 3. Chat streaming protocol (SSE)

`POST /chat/conversations/{id}/messages` and `/resume` respond with `text/event-stream`. Events (`event:` name,
`data:` JSON):

| Event | Payload | Notes |
|-------|---------|-------|
| `run_started` | `{run_id, turn}` | |
| `status` | `{stage: classifying\|retrieving\|planning\|executing, detail?}` | UI progress |
| `tool_call` | `{name, status: started\|ok\|denied\|error}` | Names only; no arguments |
| `token` | `{text}` | Re-identified text delta (see note) |
| `citations` | `{items: [{n, chunk_id, document_id, version_no, title, heading_path, page}]}` | After verification |
| `interrupt` | `{proposal_id, kind, card: {...}, expires_at}` | Confirmation card; the stream ends after this event |
| `error` | `{type, title, request_id}` | Problem-style; stream ends |
| `done` | `{run_id, outcome, usage: {input_tokens, output_tokens, provider, model}}` | Stream ends |

Streaming and re-identification: tokens are re-identified on the fly by a buffered matcher that holds back any
suffix that could be the prefix of a placeholder (`[A-Z_]+_\d{4}`) until it is complete or disambiguated; the
final text is re-identified once more as a whole and compared (mismatch → correction event `replace` with the
final text, P2).

## 5. Internal token for the worker
The worker calls no HTTP API; it uses services directly. n8n is the only consumer of `/internal/*`, authenticated
with Keycloak client credentials (`automation` role) and additionally restricted by network (not proxied by nginx).

## 6. Contract testing
- Schemathesis-style property tests run against the OpenAPI document for 4xx/5xx consistency (P2).
- `openapi-typescript` generates the frontend client at build time; CI fails on drift between the committed
  snapshot and the generated document.
